VORTEX UI HAND-OFF NOTES (updated 2025-11-22)
============================================

1. ARCHITECTURE SNAPSHOT
------------------------
- Workspace layout
  * Native core (C++): src/vortex, entry_main.cpp wires up vortex::App which embeds CEF UIApp.
  * UI bundle: ui/vortex-ui-skeleton (Vite). Built assets are loaded by native shell through cef_cache/.../index.html.
  * Shared docs/tests live under docs/, test/ (C++), ui/vortex-ui-skeleton/src/app/__tests__ (React).
- Bridge layers
  * `src/bridge/vortex.ts` discovers whichever JS bridge the shell exposes (window.vortexCall / cefQuery fallback) and normalizes calls (`Vortex.*`).
  * `src/bridge/engine.ts` is thin wrapper for eventing (currently `onNodeUpdate`) and synchronous fire-and-forget APIs (play/stop/etc.).
- React/Recoil data flow
  * `projectPathAtom`, `graphSnapshotAtom`, `selectedNodePtrAtom`, etc. hold canonical UI state.
  * Hooks (`useProjectPersistence`, `useProjectCommands`, `useEngineNodeUpdates`) are the glue between UI intent, persistence, and engine events.
  * `GraphPanel` consumes `graphSnapshotAtom` and mirrors it into ReactFlow nodes/edges; `InspectorPanel` reads same atom for metadata.
- Rendering stack
  * ReactFlow handles graph layout/editing; custom nodes defined in `src/app/components/CustomNode.tsx`.
  * UI uses Tailwind-style utility classes defined in `index.css`/`AppShell` components; docking layout via react-mosaic-component.

3. ENGINE ↔ UI CONTRACT
------------------------
- Native side
  * `vortex::App::OnNodeUpdate` gets invoked by nodes when `UpdateNotifier` fires (property changes, e.g., SetProperty notify=true).
  * App packages the update as `_ui_app.SendUIMessage(u"node_update", double(nodePtr), int32(propertyIndex), std::string(value))`.
- Browser side
  * `engine.onNodeUpdate(cb)` attaches DOM listener to window `cef-message` events (detail { name, args }).
  * Values arrive as strings; helper tries JSON.parse, falls back to raw string.
- Property lookups
  * To avoid extra C++ instrumentation we inspect `Vortex.getNodeProperties(nodePtr)` (currently returns JSON schema) and build index->name map.
  * Map cached per node, invalidated only if `pendingPropertyFetch` completes.
- Supported property types
  * `position`: JSON object { x, y }. Hook ensures numbers and updates both `node.position` and `node.props.position`.
  * `label`: plain string; UI normalizes empty string to fallback "Node" label.
  * Everything else stored under `node.props[propName]` (status/severity/fps etc.) for downstream consumers (CustomNode, Inspector).
- Client→engine updates
  * Node drag end in ReactFlow -> Vortex.setNodeProperty(ptr, "position", JSON.stringify(position)). Engine is expected to broadcast back same update.
  * Label edits from Inspector -> Vortex.setNodeProperty(ptr, 'label', value).
  * Missing pieces: there is currently no event for node creation/removal/edge updates; UI assumes command succeeded and updates snapshot optimistically.

4. ROUTING / FLOW
-----------------

- Splash now only auto-redirects to Hub; continuing last project is manual.
  * Users can enable the auto-continue toggle (from Splash or Hub) if they want Splash to open the last project automatically.

7. HOW TO CONTINUE
------------------
Step-by-step workflow for new developer:
1. `cd ui/vortex-ui-skeleton && npm install` (first time) then `npm run dev` if you want hot reload; otherwise run native shell which loads dist build.
2. Launch native app (vortex.exe) so CEF hosts UI.
3. App boot sequence: Splash -> Hub. Use Continue CTA or "Open…" to select a `.vortex` project. This sets `projectPathAtom` via `useProjectCommands.loadProject`.
4. `useProjectPersistence` observes `projectPathAtom`, loads snapshot via `projectPersistence.load`, hydrates Recoil atoms (meta/settings/graph).
5. DockLayout renders GraphPanel/Inspector once persistence sets `isHydrated=true`.
6. Graph editing writes directly to Vortex bridge for node operations; `useEngineNodeUpdates` mirrors any native-side changes back into Recoil state.
7. Before pushing code, run `npm run typecheck` (and native builds/tests if C++ touched). Optionally `npm run build` to verify production bundle.

Debug tips:
- Enable `console.log` inside `useEngineNodeUpdates` to verify property events (wrap with condition to avoid noisy logs in prod).
- If nodes stop updating, ensure `DockLayout` still mounts hook (no duplicate React roots) and that native App is calling `SetPropertyUpdateNotifier`.
- Graph not hydrating? Check `projectPersistence.load` logs and browser devtools localforage entries.

9. GRAPH STATE SCHEMA
---------------------
- `GraphSnapshot`: { nodes: GraphNodeSnapshot[], edges: GraphEdgeSnapshot[] }.
- `GraphNodeSnapshot`: { id, type, label?, position {x,y}, ptr?, props? }.
  * `id` string is ReactFlow node id; `ptr` is numeric engine pointer (double-casted).
  * `props` is arbitrary record mirrored from engine (status/progress, etc.).
- `GraphEdgeSnapshot`: { id, source, target, animated? } – currently only supports single input/output per node (loose contract).
- Persistence (src/services/persistence/index.ts)
  * `coerceGraphSnapshot` converts engine DTO (nodes[].pos, params) into snapshot.
  * Local snapshot store keeps JSON in IndexedDB via localforage; also caches recents list.

10. KNOWN LIMITATIONS / TODOs
-----------------------------
- No reconciliation if engine deletes a node outside UI: we rely on node_update to infer presence. Need explicit removal events.
- Edge list does not sync from engine; GraphPanel shows stale connections if engine modifies graph behind UI.
- Property schema caching never expires; if node type changes dynamic props, UI might ignore new fields until reload.
- Splash auto-redirect delay is fixed; consider making it configurable or storing last action preference.
  * Auto-continue toggle now stored per-user (localStorage key `vortex.splash.autoContinue`) and can be changed from Hub or Splash. Still consider exposing delay/timeout controls.
- Tests missing for new hooks; manual testing only (npm run typecheck + interactive dev session).

11. ENGINE API SUMMARY

- Vortex bridge methods (src/bridge/vortex.ts)

- Engine wrapper (src/bridge/engine.ts)

- When adding new endpoints, extend both `cefBridge.ts` (TypeScript types) and `bridge/vortex.ts` (call wrapper).
